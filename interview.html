Interview Kit

How the Meta Production Engineering intern process works, what each round probes, how to structure answers, 150+ rapid-fire questions with model answers, flashcards, and a readiness checklist.

The Meta PE process & what each round tests

Typical flow (intern / new grad PE)Recruiter screen → technical phone screen(s): usually one coding (practical scripting in Python: parse/aggregate data, string/dict/list manipulation, maybe a small simulation) and one systems ("live technical"): Linux internals + networking + troubleshooting + light design, 45 min, conversational. Onsite/virtual loop (full-time) adds: systems deep-dive, networking, system design, and behavioral. The live technical you have incoming is the systems one: expect breadth, follow-ups, and "what happens when / what if it breaks."

What interviewers are scoring

Depth on demand

Can you go from "DNS resolves the name" down to "UDP 53, recursive vs authoritative, TTL, what the stub resolver caches" when pushed? Say the simple version first, then offer to go deeper.

Structured debugging

Observe → hypothesize → test, naming tools and interpreting their output. Never jump to a fix without evidence. Ask what the symptoms are.

Failure thinking

For every component: how it fails, how you'd detect it, blast radius, mitigation. Volunteer this without being asked.

Trade-off language

"It depends on X; if read-heavy I'd…, if strong consistency is required I'd…". No absolutes.

Communication

Think aloud, check in ("want me to go deeper on the TCP side or move on?"), draw, summarize. Admit unknowns gracefully and reason from first principles.

Operational mindset

Automation over heroics, monitoring, runbooks, rollbacks, capacity headroom, postmortems. This is what separates PE from SWE answers.

Answer templates

Definition (1 sentence) → why it exists / problem it solves → how it works (3–5 steps) → trade-offs / failure modes → where you'd see it in practice. Example: "Load average is the average number of runnable + uninterruptible tasks over 1/5/15 min. It exists to summarize demand on the CPU/IO. Compare it to core count… D-state tasks inflate it during I/O stalls, so I'd confirm with vmstat/iostat… In practice I alert on load per core trending up alongside latency."

Go layer by layer, in order, at a consistent depth, then offer a dive: "That's the overview — I can go deeper on DNS, the TCP handshake, TLS, or the server side; where would you like?" Keep a mental list of 2 failure modes per layer to drop in.

Clarify (what exactly is slow/broken, since when, what changed, scope) → triage impact & mitigate if possible (rollback?) → systematic investigation from the outside in or from the resource up (USE) → state hypotheses with the evidence that would confirm/refute → fix → prevent (alert, automation, runbook). Narrate what each command output would mean. Ask the interviewer for the output — it's interactive.

Requirements (functional + non-functional) → estimates → API & data model → high-level diagram → deep-dive the hard parts → failure modes, monitoring, rollout, scaling 10×. Timebox. Ask which part they care about most. For PE: emphasize operability: how it's deployed, monitored, debugged, degraded.

STAR (Situation, Task, Action, Result) + what you learned. Prepare: a time you debugged something hard; dealt with ambiguity; disagreed with someone; made a mistake (and the postmortem mindset); automated something tedious; learned a new system fast. Meta values: move fast, be bold, focus on impact, be open, build social value.

Question bank: Linux & OS

What happens when you run ls in a shell?
Shell parses the line, checks builtins/aliases, searches $PATH; fork() creates a child (COW); child sets up redirections (dup2) and execve("/bin/ls"); kernel loads the ELF, ld.so maps libc; ls calls openat(".") + getdents64 to read directory entries, stat/lstat for -l, write(1) to the tty; exit → SIGCHLD → shell waitpid() reaps, prints prompt. Mention: PATH lookup, COW, FD inheritance, exit status in $?.
What is a zombie process? An orphan?
Zombie: exited, but parent hasn't wait()ed — kernel keeps PID + exit status. Can't be killed (already dead); fix the parent or kill it so init adopts and reaps. Orphan: parent died first; re-parented to init/subreaper, which reaps it when it exits.
Process vs thread?
Process: own address space, FDs; isolation; heavier to create/switch. Thread: shares address space & FDs within the process; own stack/registers; cheap communication, data races. Linux: both are tasks via clone() with different sharing flags.
What is virtual memory and why do we want it?
Per-process private address space mapped to physical frames by page tables + MMU/TLB. Gives isolation/protection, lets programs use more memory than RAM (swap), enables sharing (libs, COW), lazy allocation, and simplifies linking (fixed addresses).
Explain a page fault.
Access to a virtual page not currently mapped/valid traps to the kernel. Minor: page is in RAM (first touch, COW, page cache) → map it. Major: must read from disk (swap or file) → slow. Invalid: SIGSEGV.
What does free output mean; why is "free" small?
Linux uses idle RAM as page cache (buff/cache) and drops it on demand; "available" = what apps can get. Small "free" is healthy. Worry when available is low or swap in/out is sustained.
What is swap, and should prod servers have it?
Disk space for evicted anonymous pages. Pro: survive brief spikes, free RAM for cache. Con: thrashing is slow death vs fast OOM. Many fleets run no swap or minimal swap with low swappiness; k8s historically required swap off. Know both sides.
How does the OOM killer choose?
Highest oom_score (≈ % of memory used, adjusted by oom_score_adj). Logs to dmesg. cgroup limits trigger per-container OOM. Protect critical daemons with negative adj.
What is a file descriptor? What does 2>&1 do?
Integer index into the process's table of open files (0 stdin, 1 stdout, 2 stderr). 2>&1 dup2's FD 1 onto FD 2 so stderr goes wherever stdout currently points — order matters (cmd > f 2>&1 vs cmd 2>&1 > f).
What is an inode? Hard vs soft links?
On-disk metadata structure (mode, owner, size, timestamps, block pointers), not the name. Directory entries map names → inode numbers. Hard link: another name, same inode, same FS. Symlink: separate file containing a path; can dangle; crosses FS.
Difference between kill, kill -9, and kill -HUP?
kill sends SIGTERM (15) — catchable, graceful. -9 SIGKILL — uncatchable, immediate, no cleanup. -HUP (1) — conventionally "reload config" for daemons.
What is a system call? Give examples and how to observe them.
The controlled entry from user mode into the kernel (trap instruction). open/read/write/close, fork/execve/wait, mmap/brk, socket/connect/accept, ioctl, epoll_wait. Observe with strace (-f -tt -T), perf trace, or BPF.
What's in /proc?
Kernel-exported virtual files: per-PID info (status, fd, maps, cmdline), system state (meminfo, cpuinfo, loadavg, stat), tunables (sys/ = sysctl), network tables (net/). Reading them invokes kernel code; it's what ps/top/free parse.
How does top compute %CPU?
Reads /proc/PID/stat utime+stime (jiffies) at two points and divides the delta by elapsed time × ticks/sec; system-wide from /proc/stat. So it's an average over the refresh interval.
Explain cgroups and namespaces in one sentence each.
Namespaces limit what a process can see (PIDs, network, mounts, hostname, users). cgroups limit what it can use (CPU, memory, I/O, pids). Together + overlayfs + capabilities/seccomp = a container.
What happens during boot?
Firmware (POST) → bootloader (GRUB loads kernel + initramfs) → kernel init, mounts initramfs, loads drivers, switch_root → systemd (PID 1) starts units toward default target → getty/sshd. Debug with dmesg, journalctl -b, systemd-analyze.
Blocking vs non-blocking I/O; what is epoll?
Blocking: the call waits until done. Non-blocking: returns EAGAIN immediately; you need a readiness mechanism. epoll: register FDs once, epoll_wait returns ready ones in O(ready) — basis of event-loop servers (nginx, Node, Redis).
Why might a process be unkillable?
D state (uninterruptible I/O, e.g., hung NFS) — signal delivered only when the syscall returns; or a zombie (already dead); or PID 1 in a container (kernel ignores default-action signals for init).
What is the difference between a mutex and a semaphore? What is a deadlock?
Mutex: binary ownership lock (only the owner unlocks). Semaphore: counter allowing N holders, signal from anyone. Deadlock: cycle of threads each holding a lock the next needs; requires mutual exclusion, hold-and-wait, no preemption, circular wait; prevent by lock ordering/timeouts.
What's the difference between nice and real-time priority?
nice (−20..19) is a weight within the normal CFS class; RT classes (SCHED_FIFO/RR, prio 1–99) always preempt normal tasks and can starve the system if they spin.

Question bank: Networking

Describe the TCP three-way handshake and why it exists.
SYN(seq=x) → SYN-ACK(seq=y, ack=x+1) → ACK(ack=y+1). Synchronizes initial sequence numbers both ways, confirms bidirectional reachability, negotiates options (MSS, window scale, SACK). Costs 1 RTT before data.
What is TIME_WAIT and is it a problem?
State held by the side that closed first for 2×MSL (60 s on Linux) to absorb late packets and ensure the final ACK is received. Normally harmless; thousands on a client/proxy can exhaust ephemeral ports → use keepalive/pooling, tcp_tw_reuse, more source IPs.
What is the MTU and what goes wrong with it?
Max frame payload (1500 on Ethernet). Larger IP packets fragment, or if DF is set, get dropped with an ICMP "fragmentation needed" message. If ICMP is blocked, PMTU discovery fails → small packets work, large ones hang (blackhole). Tunnels/VXLAN reduce effective MTU. Test with ping -M do -s.
How does DNS resolution work end to end?
App → stub resolver (hosts file, cache) → recursive resolver → iterates root → TLD → authoritative, caching per TTL → returns A/AAAA. UDP 53, TCP for large/zone transfers. Failure modes: resolver timeouts (5 s), stale caches, low TTL storms, NXDOMAIN caching.
Difference between a switch and a router?
Switch: L2, forwards Ethernet frames by MAC within a broadcast domain, learns MAC→port. Router: L3, forwards IP packets between networks using a routing table, decrements TTL, rewrites L2 headers each hop.
What is NAT and why does it complicate things?
Rewrites private addresses to a shared public one, tracking connections in a table. Breaks inbound connectivity (needs port forwarding/STUN), introduces state (table exhaustion, idle timeouts dropping long-lived connections), hides client IPs.
What does a load balancer health check do and how can it hurt?
Periodically probes backends; removes failing ones. Hurts when: a deep check depends on a shared dependency (DB blip removes ALL backends), too-aggressive thresholds flap, or health endpoint is slow under load, causing removal exactly when capacity is needed. Use shallow checks + hysteresis + minimum-healthy-percent (panic threshold).
How does HTTPS protect data; what does a certificate prove?
TLS: asymmetric handshake authenticates the server (cert signed by trusted CA, hostname in SAN) and establishes a symmetric session key via ECDHE (forward secrecy); then AES-GCM encrypts & authenticates data. The cert proves the holder of the private key controls that domain per the CA.
What is the difference between latency and bandwidth? How does RTT limit throughput?
Latency: time per bit to arrive (RTT); bandwidth: bits per second capacity. TCP throughput ≤ window/RTT; long RTT with small windows caps throughput regardless of link speed; also every sequential round trip (DNS, TCP, TLS) adds latency — minimize round trips.
How would you find which process is listening on a port, and what's connected to it?
ss -ltnp 'sport = :8080' for the listener; ss -tnp state established '( sport = :8080 )' for peers; lsof -i :8080 alternative.
What is BGP and how did it take Facebook offline in 2021?
BGP exchanges prefix reachability between autonomous systems. A maintenance command withdrew the routes to FB's DNS servers' prefixes (the backbone appeared unhealthy so the DNS servers deliberately withdrew their anycast announcements); with DNS unreachable, every property failed, and internal tools depending on the same infra were also down, slowing recovery.
UDP packets are being dropped on a receiving host. Where could the drops happen?
NIC ring buffer overrun (ethtool -S rx_dropped → increase ring, RSS/irqbalance), softirq backlog (/proc/net/softnet_stat), socket receive buffer full because the app reads too slowly (UDP: RcvbufErrors in nstat → increase rmem, read faster/batch), firewall/conntrack, upstream network loss (mtr).
What's the difference between HTTP keep-alive and HTTP/2 multiplexing?
Keep-alive reuses one TCP connection for sequential requests (still one at a time). HTTP/2 interleaves many concurrent request/response streams on one connection with binary framing and header compression.
How does a CDN decide which edge serves a user?
DNS-based (resolver location → nearest PoP IP; imprecise with public resolvers, EDNS client subnet helps) or anycast (BGP routes to nearest). Then the edge checks cache; misses go to a regional shield then origin.

Question bank: System design & distributed systems

How do you scale a web app from 1 server to millions of users?
Separate web and DB → stateless app servers behind an LB → cache (CDN for static, Redis for data) → DB read replicas → async work via queues → shard the DB → multi-region with GeoDNS; add observability, autoscaling, and resilience patterns at each step. Name the bottleneck that forces each step.
Vertical vs horizontal scaling trade-offs?
Vertical: simple, no distribution problems, hard ceiling, SPOF, expensive at the top. Horizontal: near-unlimited, fault-tolerant, cheaper hardware, but requires statelessness/partitioning and brings consistency, coordination, and ops complexity.
Explain CAP in 30 seconds with an example.
During a network partition you must choose: refuse some requests to stay consistent (CP: ZooKeeper, a bank ledger) or answer with possibly stale data to stay available (AP: Cassandra, DNS, a shopping cart). When there's no partition you still trade latency vs consistency (PACELC).
What is eventual consistency; how do you cope with it as a developer?
Replicas converge over time if writes stop; a read may be stale. Cope with: read-your-writes routing, idempotent writes, version numbers/vector clocks, designing UIs to tolerate lag, conflict resolution (LWW/merge/CRDT), and using strong consistency only where required.
Why shard, and how do you choose a shard key?
When data/write load exceeds one node. Choose a key that: spreads load evenly (high cardinality, no hot values), keeps data that's queried together on one shard (user_id for a user's data), and rarely needs cross-shard operations. Avoid monotonically increasing keys for range sharding (hot last shard).
Leader-based replication: sync vs async?
Sync: no loss on failover, higher write latency, availability tied to replica health. Async: fast, replicas may lag → stale reads and potential loss of last writes on failover. Semi-sync (wait for one replica) is the common compromise.
How does a distributed cache stay consistent with the DB?
It doesn't perfectly. Cache-aside + delete-on-write + TTL bounds staleness; leases/CAS avoid stale-set races; CDC-driven invalidation makes it event-driven; version keys avoid invalidation entirely. Accept bounded staleness; read from DB for must-be-fresh paths.
Why are message queues useful? What problems do they introduce?
Decoupling, buffering bursts, async latency, fan-out, retry/DLQ. Introduce: at-least-once duplicates (need idempotency), ordering limits, lag/backpressure, another system to run, eventual consistency, poison messages.
What is a consensus algorithm and when do you need one?
A protocol (Raft/Paxos) by which a majority of nodes agree on a sequence of values despite crashes, giving a linearizable log. Needed for leader election, distributed locks, config/metadata stores, replicated state machines — not for bulk data.
How do you make a system highly available?
Remove SPOFs with redundancy across failure domains; health-checked load balancing; replication with automatic failover; stateless tiers; timeouts/retries/circuit breakers; graceful degradation; capacity headroom (N+1); safe deploys (canary/rollback); monitoring with SLO-based alerting; drills.
Define SLI, SLO, SLA, error budget.
SLI: a measured indicator (success ratio, latency under threshold). SLO: internal target for the SLI over a window. SLA: external contract with penalties. Error budget = 1 − SLO: allowable unreliability that governs release velocity vs reliability work.
What's the difference between monitoring and observability?
Monitoring: predefined checks/dashboards for known failure modes. Observability: enough rich telemetry (metrics, structured logs, traces with high-cardinality context) to ask new questions about unknown failures without redeploying.
How would you roll out a risky change to 100k hosts?
Canary small %, compare metrics vs control, staged by failure domain/region, automatic halt/rollback on SLO regression, bake time between stages, feature flag kill switch, backward-compatible data changes, comms + on-call aware.
What is backpressure?
A mechanism for a slow consumer to signal producers to slow down instead of being overwhelmed: bounded queues, blocking writes, TCP window, 429/503 with Retry-After, credit-based flow control. Without it, systems buffer until they OOM or latency explodes.
Idempotency: what and why?
Repeating an operation has the same effect as doing it once. Required because networks force retries and queues deliver at-least-once. Achieve via natural idempotence (PUT, set), idempotency keys with dedup store, or conditional writes (version checks).
What is a hot key/hot shard and how do you fix it?
One key or partition gets disproportionate traffic (celebrity, viral item). Fixes: replicate the key across N copies (suffix), local caching, split the partition, dedicated capacity for whales, write aggregation.
Compare SQL and NoSQL for a new product.
Default to SQL (Postgres/MySQL): transactions, flexible queries, mature ops; scale with replicas/cache; shard when needed. NoSQL when: extreme write scale with simple access patterns (Cassandra), key-value latency (Redis/Dynamo), flexible documents, or graph/time-series/search specialization. Choice is about access patterns and consistency needs.
How do you estimate capacity for a new service?
Expected QPS (DAU × actions / 86400, ×peak factor), payload sizes → bandwidth/storage, per-host capacity from load tests (not guesses), add headroom (target ~50–60% utilization), N+1/N+2 for failure domains, growth forecast, and hardware lead time. Re-validate with real traffic.
What is a thundering herd? Give three places it shows up.
Many actors waking/acting simultaneously and overwhelming a resource: cache key expiry (stampede), clients reconnecting after an outage, cron jobs at :00, config push causing fleet-wide fetch, accept() wakeups in old kernels. Fixes: jitter, coalescing, leases, staged ramps.

Question bank: PE scenario / judgment

You're on call. An alert says error rate is 5% on the API. Walk me through your first 10 minutes.
Ack; open dashboards: scope (all regions/endpoints?), since when, correlate with deploys/config/infra changes; check dependency health; if a change correlates → roll back; if a host/AZ → drain it; if overload → shed/scale; declare an incident if impact persists; communicate; then root-cause after mitigation.
How do you decide what to automate?
Toil that is manual, repetitive, automatable, tactical, and scales with service growth. Prioritize by frequency × time × risk. Start by scripting the runbook, add safety (dry run, rate limits, approvals), then make it self-healing where safe.
A teammate wants to ship a hotfix straight to 100% on a Friday night. What do you say?
Ask about the risk vs the current impact: if the outage is severe, a fast rollout with canary verification and a ready rollback is justified; otherwise stage it and wait. Make sure someone is watching metrics and the rollback is tested. Blameless framing, decision based on error budget/impact.
How would you monitor a new service from day one?
RED metrics (rate, errors, duration histograms) per endpoint; USE for hosts; structured logs with request IDs; tracing; SLOs with burn-rate alerts; dashboards for dependencies; synthetic probes; a dead-man's switch on the monitoring pipeline.
How do you write a good postmortem?
Timeline with timestamps, impact quantified, detection & response analysis (TTD, TTM), root cause and contributing factors (systemic, blameless), what went well/poorly/lucky, prioritized action items with owners and due dates, lessons shared broadly.
Your fleet of 5000 hosts needs a kernel upgrade. Plan it.
Test in staging; canary on a small batch with soak time; roll by failure domain respecting capacity (never below N+1), drain → upgrade → reboot → health check → undrain; automatic pause on anomalies; rollback plan (previous kernel in GRUB); track progress in a dashboard; schedule around traffic peaks.

Flashcards (click to flip)

Load average counts…
Runnable (R) + uninterruptible sleep (D) tasks, averaged over 1/5/15 min. Compare to core count.
Consistent hashing moves how many keys when adding a node?
≈ K/N (just the new node's share), vs almost all with mod-N.
TIME_WAIT duration on Linux
60 s (2×MSL). Held by the side that closed first.
Quorum condition for consistent reads
W + R > N
Exit code 137 means…
128 + 9 → killed by SIGKILL (often the OOM killer / docker kill).
99.9% availability = downtime per month
≈ 43.8 minutes. 99.99% ≈ 4.4 min. 99.999% ≈ 26 s.
Raft needs how many nodes to tolerate f failures?
2f + 1 (3 tolerates 1, 5 tolerates 2).
502 vs 503 vs 504
502: upstream returned garbage/refused. 503: service unavailable/overloaded (server itself). 504: upstream timed out.
Default ulimit -n
1024 open files per process — raise it for servers (LimitNOFILE).
Little's law
L = λ × W (in-flight = throughput × latency). Sizes pools and queues.
Minimum TCP RTO on Linux
200 ms — a single lost packet without fast retransmit costs ≥ 200 ms (tail latency!).
Four golden signals
Latency, Traffic, Errors, Saturation.
Deadlock's four conditions
Mutual exclusion, hold & wait, no preemption, circular wait.
Cache-aside write path
Write DB, then DELETE the cache key (don't update) — next read repopulates.
DNS record for aliasing; its limitation
CNAME — cannot coexist with other records at the same name, so not at the zone apex (use ALIAS/ANAME).
Fork + exec: which syscall copies memory?
Neither copies eagerly: fork shares pages copy-on-write; exec replaces the image.
